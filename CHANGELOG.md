# Changelog

This file is a best-effort, occasionally-updated log of notable changes — it
is not kept current with every commit. `git log` and PR titles are the
authoritative history; no versioned release has been tagged yet, so there's
nothing here to hold to [Semantic Versioning](https://semver.org/spec/v2.0.0.html)
against. Entries below follow the [Keep a Changelog](https://keepachangelog.com/en/1.1.0/)
style when they are written.

## [Unreleased]

### Fixed
- Doorbell nudges no longer land in the coordinator's composer while the operator is working there. The `#430` gate only covered a pane that was *mid-turn*; a pane **between** turns reads idle, which is exactly when a human is reading and thinking — so an operator mid-conversation could take a doorbell per worker outcome (measured: seven in twelve minutes on fand-app, 2026-09-23). A doorbell is now held while a human turn has landed in the coordinator session within `COORD_HUMAN_IDLE_SECS` (600) or any own worker session within `WORKER_HUMAN_IDLE_SECS` (300), and delivers — coalesced, with a live inbox count — once they idle out. Unlike every other hold this one has **no ceiling**: a busy pane is safe to force a paste into eventually, a session someone is working in never is. Nothing is lost by waiting, since inbox payloads stay unconditional (`#430`). Detection is not a naive "read the last user turn": a pasted doorbell is recorded with `origin {kind: human}` and `promptSource "typed"`, identical in shape to hand-typed input, so the watcher's own pastes are subtracted by text match, by correlation against pastes in its own `events.log`, and by length — with every uncertainty resolving toward *ringing*, since a muted swarm is far worse than a nudge arriving while someone reads. Holding on worker **busyness** was considered and rejected (it suppresses exactly the wake that tops up a just-finished worker, and a busy swarm never goes quiet); it survives as opt-in `WAKE_DEFER_ON_SWARM_BUSY=1`. `COORD_HUMAN_IDLE_SECS=0` is a clean rollback. (#459)
- A doorbell suppressed by the wake debounce is now **held and re-rung** instead of dropped. Two workers finishing inside `DEBOUNCE_SECS` produced two inbox payloads but one doorbell; the second had no wake attached and could sit unread until some unrelated later event — ~11h in the 2026-09-22 SAMlytics incident, where a finished worker's PR waited in draft-hold the whole time for a coordinator re-ready it never learned was due. Coalescing is preserved (N held doorbells still collapse into one `Inbox: N item(s)` nudge); zero doorbells was the bug. The outcome and outbox-message debounce clocks are also collapsed into one shared, on-disk clock: they were separate globals, so two sources could each ring inside the same window, and the retry pass — a different OS process — could neither see nor reset the window it was delivering into. (#456)

- `sandbox.sh` died silently — no message, exit 1, before `docker run` — when `gh` was installed but not logged in: `_gh_token=$(gh auth token 2>/dev/null)` exits 1 in that state, and under `set -e` an assignment from a failing command substitution takes the script down. No token is a valid state (the container just gets no `GH_TOKEN`), not a fatal one. Found by the stubbed harness added for #403, which now doubles as its regression guard. (#403)
- Watcher respawn after coordinator-watch's self-kill: `llm-start.sh` decided "already running" from `pane_start_command` alone, but the swarm's `remain-on-exit` keeps the SIGKILLed pane in place *still reporting that command*, so every re-run printed "already running — skipping spawn" and started nothing. corpusminder-spring and SAMlytics ran ~23h with no watcher after the 2026-09-08 staleness self-kill (#296) fired host-wide — accumulating undelivered `worker.finish` events and finished worker windows that `WATCHER_AUTOCLOSE` should have reaped. The guard is now `watcher_pane_scan()`, which ignores dead panes and returns their indexes so the corpses are reaped before the replacement is split. New `tests/test-shape-watcher-respawn.sh` drives a real (private-socket) tmux server, since the bug is tmux's own behavior and a stub would only re-encode the wrong belief. (#391)
- `kill-finished-workers.sh`'s default mode gated solely on `is_parked()` (pane scrollback showing the listener's post-task marker), a signal that's structurally unreachable for the default interactive-`claude`-REPL worker — the REPL never exits on its own, so the listener never prints that marker and no default-mode window was ever reapable, while `Nothing to kill given current filters.` gave no hint that `--merged-only`/`--pr-finalized` would in fact reap them. Default mode now reaps on parked **OR** a MERGED upstream PR (PR state is at least as strong a "safe to reap" signal as parked scrollback); a branch whose PR is CLOSED without merging is still left alone by default but the skip line and the "nothing to kill" summary now point at `--pr-finalized`. (#386)
- `coordinator-watch.sh`'s background-shell violation sweep (`WATCH_BG_VIOLATION_SWEEP_SECS`, #298) now also scans the coordinator's own tmux pane, not just `iss-*` worker panes — the ~20h leaked poll loop the sweep exists to catch (#383/#384) happened in a coordinator pane. A coordinator sighting has no outbox to drop a message into, so it's logged as a `watch.bg_violation` event and surfaced via a new per-wake self-check in `prompts/coordinator.md`. (#385)
- The worker-finished coordinator wake channel, silently dead since ~2026-07-20: default interactive workers never exit claude, so `worker-listener.sh` never wrote the `done/*.ok.json` that is `coord.wake`'s only completion trigger — completions were detected (and reaped) by the wake-less pr-poll/check-on-done backstops while the coordinator kept reporting them in flight. `coordinator-watch.sh` now synthesizes the outcome file (`"synthesized": true`, atomic mv, `WATCH_SYNTH_OUTCOME=1` to disable with 0) the moment check-on-done wins its claim, so the whole existing inotify → `on_outcome` → autoclose → debounced-wake pipeline fires again; `prompts/coordinator.md` additionally forbids asserting in-flight status from memory — verify live windows/PR state first, and treat a vanished "in-flight" worker as a missed wake. (#314)

### Changed
- `migration-collision-check.sh`'s Flyway collision verdict now prints the actual fix instead of "rename the losing file(s) to the next free version": which file loses (the PR-side one — base-side migrations are already applied to every DB tracking the base branch, so moving one of those means `flyway repair` everywhere), the next free version computed across base ∪ head ∪ every other open PR's changed files (a merge burst otherwise hands out the number the next PR already claimed), and the `git mv` / `git commit` / `git push` lines verbatim for the PR branch. PR-internal duplicates (both claimants on the head) are named as such with no mv line. Surfaces through `swarm-merge.sh`'s gate output unchanged. Auto-applying the rename was considered and rejected — ~1 collision/week across swarms doesn't pay for a branch-mutating path plus its refuse-list; #162 stays the record of that decision.
- Workers can now run on a project-scoped GitHub token instead of the operator's. `sandbox.sh` injects the host's `gh auth token` into every worker — on this host a classic OAuth grant with `repo`+`workflow`, reaching every repository the operator can, when a worker needs write on one. A `GH_TOKEN=github_pat_…` line in `<project>/.sandbox-env` (per-project, gitignored, symlinked into every worktree, read by Docker as a file so it never touches argv) now takes precedence: when present the host token is *not* injected — previously the `-e GH_TOKEN` would have outranked the env-file value for the same key and silently handed the worker the broad credential anyway. The session header names the source (`.sandbox-env` / `host gh login` / `none`). Host-side scripts keep the operator's login; only the agents running arbitrary code shrink. `scripts/gh-token-probe.sh` verifies a candidate token against the swarm's full `gh` surface (13 read ops incl. `review-scoreboard.sh`'s GraphQL shape; write ops opt-in and throwaway-repo-only) before it goes live — baseline 15/15 on the current token; `docs/gh-token-scoping.md` carries the permission table and procedure. Known and recorded: this is the API half only — `git push` goes over the mounted SSH key, which stays account-wide. (#418)
- Commits made inside the sandbox are now authored `swarm <swarm@oconeco.dev>` instead of the host human whose credentials the swarm borrows. `sandbox.sh` mounts `~/.gitconfig` read-only, so every worker commit carried the operator's name and `git log`/`git blame`/`git shortlog` could not tell agent work from hand-written work (measured across the last 200 commits: 0 non-human authors in either active repo, while the `[agent]` PR-title marker that was supposed to cover this is prompt-enforced — a worker that forgets it produces an indistinguishable PR — and had reached 93/200 in fand-app and 0/200 here, never having travelled between repos). The override rides the `docker run` line, so it applies whether or not the agent cooperates, in every project, for every agent CLI. **Author only:** the committer stays the host identity, so `git log --format='%an|%cn'` reads as "agent wrote it, human shipped it" and commit signing (which covers the committer) is untouched. The name is vendor-neutral on purpose so it stays true when the CLI behind a worker changes. `SWARM_GIT_AUTHOR_NAME`/`SWARM_GIT_AUTHOR_EMAIL` override; `SWARM_GIT_IDENTITY=0` restores the old behaviour. Not covered, deliberately: GitHub's squash merge collapses mixed-author branches to a single author (the `[agent]` title prefix remains the trunk-level marker), PRs are still opened by the shared `gh` token, and the host-side coordinator runs outside the sandbox. (#403)
- The swarm's two PR warning comments now carry next steps instead of just a warning. `SWARM_PENDING_BRIEF: queued` (`requeue.sh`) said "merging now may ship without this queued fix" and stopped there, leaving a reader in the GitHub web UI — with neither the brief nor a shell on the swarm host — nothing to act on; `SWARM_BRIEF_ORPHANED` (`kill-worktree.sh`) offered "a human should judge whether the queued work is still relevant" plus a directory path. Both now open with a **delivery outlook** (`requeue.sh` already probed the listener state for a terminal hint nobody reads: a live idle `iss-<N>` window blesses waiting, while no listener or no session says "nothing is polling this brief" and "Do not just wait" — the case where waiting for the `cleared` comment never resolves), carry a collapsed excerpt of the brief itself so a review BLOCK is distinguishable from a nit (`SWARM_PR_BRIEF_LINES`, default 20; `SWARM_PR_BRIEF_EXCERPT=0` to suppress; six-or-more-backtick runs defanged so a brief cannot break out of the comment's fence), and close with numbered copy-pasteable commands for each disposition — inspect/merge-anyway-with-a-follow-up-issue/cancel, and read/re-file/drop respectively. Brings both up to the bar `migration-collision-check.sh`'s `SWARM_MIGRATION_GATE` comment has always met with its `Remediation:` lines. (#397)
- The coordinator is now foreground-only too: `scripts/coordinator-claude.sh` exports `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1` unless `COORDINATOR_ALLOW_BACKGROUND_TASKS=1`. #301 below covered worker containers only, and the leak that closed this gap was a coordinator — an `until tmux capture-pane -t iss-873 | grep -qE 'APPROVE|BLOCK'; do sleep 20; done` loop started in the *foreground* (invisible to an operator hook that only inspects `run_in_background`), promoted to a background task by the harness, watching a window that had since been reaped so its exit condition could never fire: ~20h. `tests/test-scripts.sh` now guards the coordinator launcher the same way it guards `sandbox.sh`, and registers it in the checked-script list — it was absent, which is how one-role-only coverage went unnoticed. (#383)
- `SWARM_WORKTREE_GROUPING`'s shipped default (`.env.example`) flips from `flat` to `project`: new worktrees land at `<parent>/<project>-worktrees/wt-issue-N` instead of `<parent>/wt-issue-N`, closing the cross-project namespace collision flat grouping is prone to on hosts running multiple swarms under one parent dir (real incident, 2026-08-12: a collision forced a coordinator to manually `git worktree remove` a sibling swarm's still-open-PR worktree). `flat` remains supported — set `SWARM_WORKTREE_GROUPING=flat` in `<project>/.swarm/.env` to keep it. **Migration for existing flat-layout hosts:** nothing auto-migrates; `llm-start.sh` now warns (non-fatal) at startup when it finds legacy flat worktrees for the current project sitting unmanaged under the new default — finish them out or `git worktree move` them onto the new path by hand. (#271)
- Worker containers now set `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1`: claude workers can no longer start background Bash tasks (nor have timed-out foreground commands silently promoted to background), closing the unkillable-poll-loop leak — e.g. an `until gh run list ... | grep -q <sha>; do sleep 5; done` watch left running for 7h+ after the sha was force-pushed away. `prompts/worker.md` now also names CI watching (`gh run watch`, sha-poll loops) as the classic case of the foreground-only rule, which still binds gemini/codex workers. (#301)
- Worker end-of-task output: the `## Summary` + `## Decision` + `## Next` triad is now a single terminal `## Handoff` block (**What** / **Decide** when a decision is open / **Action** with PR link + risk), emitted last in the pane — bottom line at the end, since the operator reads panes bottom-up and triages on the GitHub PR page. Mid-task `## Decision`/`## Note` blocks and the PR-body skeleton are unchanged. (#280)

### Removed
- The four-level `WORKER_VERBOSITY` dial (`verbose`/`normal`/`concise`/`spartan`, ADR 0002) and its plumbing: `provision-worker.sh -v/--verbosity` flag, env resolution chain, per-brief `## Worker verbosity` injection, and the `sandbox.sh`/`llm-start.sh` passthrough entries. Workers now speak with one baked-in voice (`prompts/worker.md` § "Worker voice"): status at milestones, options only at genuine decision points. (#279)

### Added
- `coordinator-watch.sh` now has a durable inbox (`<project>/.swarm/coord-inbox/`, mirroring the worker-outbox mktemp+mv/`processed/` convention) and only wakes the coordinator's composer when it's idle. Every outcome/outbox/activity-poll finding is written to the inbox FIRST, before any doorbell paste is even attempted — the exact fix for a `coord.wake.submit_failed` losing content that "existed nowhere but the failed paste." The doorbell itself shrinks to a one-line nudge (`Inbox: N item(s)...`) and now checks `coordinator_pane_busy()` before pasting: a mid-turn coordinator used to get a paste queued and delivered as an unrelated `❯` user turn spliced into whatever it was already doing (fand-app swarm, PR #1108 merge turn, 2026-09-16) — it's now deferred instead, retried every `COORD_WAKE_BUSY_RETRY_SECS` (default 30s), and delivered anyway after `COORD_WAKE_BUSY_CEILING_SECS` (default 15min) so a long turn can't starve a wake forever (`coord.wake.defer` / `coord.wake.defer_ceiling` events). Activity-poll findings are now inbox-only with no doorbell at all — they're never urgent enough to interrupt a turn. `prompts/coordinator.md`'s new "Inbox" section has the coordinator-side triage contract: scan at the start of every turn and after finishing an operator's request, never mid-stride. (#430)
- `scripts/reap-orphan-worktrees.sh` — bulk-reap stale `wt-issue-*` worktrees whose work is preserved elsewhere. Iterates directories (unlike `kill-finished-workers.sh`, which iterates live `iss-*` tmux windows), so it catches worktrees that outlived their tmux session. Default safety predicate: at least `--min-age-days N` old (default 2; overridable via `REAP_MIN_AGE_DAYS`), clean tree, and PR finalized (MERGED or CLOSED). Stricter `--merged-only` and offline `--no-pr-check` modes available.
